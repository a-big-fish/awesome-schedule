# Web 使用与运维

本页面向自建 Awesome Schedule 服务的用户。首次运行和公开部署配置见 [项目 README](../README.md)。

## 简历助手

从「我的面试」上传带文字层的 PDF，再打开「简历助手」。

- 「练一练」围绕当前简历生成问题，可选参考当前账号有权读取的相关个人面经题目。
- 「简历优化」逐条检查技术栈、项目职责、量化证据、句式和篇幅。建议可以定位到原文所在的 PDF 页。分析历史和对应简历关联，按当前账号权限读取。
- 每次优化可选一个或两个模型。两个模型并行分析相同材料，建议在各自的结果栏逐条显示。中途截断时保留已经校验并显示的建议。
- 分析和练习会向选用的模型服务发送处理后的文本和本次输入。服务端会过滤识别到的姓名及联系方式。选择自定义接口时，请按该服务的隐私条款处理简历资料。

## 模型配置

### 服务默认模型

将 [环境变量示例](../.env.example) 复制为本机 `.env`，填写以下配置后重启 Web 服务。

| 设置 | 用途 |
| --- | --- |
| `AI_PROVIDER` | 外部模型使用 `openai_compatible` |
| `AI_API_BASE_URL` | 默认模型服务的 API 地址 |
| `AI_API_KEY` | 默认模型服务的 API Key |
| `AI_MODEL` | 服务支持的模型 ID |
| `AI_TIMEOUT_SECONDS` | 模型接口的单次网络等待配置 |
| `AI_REASONING_EFFORT` | 简历优化的推理强度，适配器按模型和网关兼容性处理 |

### 账号自定义模型

在公开个人模式中，从「个人设置 → AI 模型」管理接口。简历优化的模型选择区也提供添加入口。填写公开 HTTPS API URL 和 API Key，获取模型列表后选择模型。服务需支持 OpenAI 兼容的模型列表与流式 Chat Completions。

自定义模型按账号隔离。API Key 加密存放于 `RESUME_MODELS_DB_PATH` 指定的本机数据库，默认是 `data/resume-models.sqlite3`。应用将解密密钥保存到同位置的 `.key` 文件。迁移时同时迁移数据库和对应密钥，两者都应限制文件访问权限。简历及优化历史使用配置的简历文件存储。

## 运行日志

默认日志路径为 `data/logs/`。启动阶段的问题也可在启动终端查看。

| 文件 | 记录内容 |
| --- | --- |
| `app.log` | 应用运行日志、HTTP 请求摘要、Uvicorn 和数据库连接池日志 |
| `error.log` | 错误级日志及 HTTP 5xx |
| `resume_parser.log` | 简历解析详情 |

响应头 `X-Request-ID` 可与请求摘要和简历优化日志关联。请求摘要耗时用于排查本地接口，模型生成时间看同一请求 ID 下的 `Resume model upstream` 和 `Resume model review`。前者记录上游响应头、首次推理、首次正文、总时长和结束原因。后者记录第一条有效建议、总时长及建议条数。

日志支持 `LOG_DIR`、`LOG_MAX_BYTES` 和 `LOG_BACKUP_COUNT`。应用日志与错误日志默认每份达到 10 MiB 后轮转，各保留 5 份备份。日志通过有界队列异步写入，高峰时可能丢弃新日志。部署多个 Web 工作进程时，为每个进程分配独立日志目录。

HTTP 摘要省略请求正文、Cookie 和查询参数。模型诊断记录阶段和计数。请将运行日志、数据库、密钥及上传的简历文件保存在部署环境。
